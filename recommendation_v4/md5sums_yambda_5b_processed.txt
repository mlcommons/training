# MD5 checksums for the preprocessed yambda-5b dataset (processed_5b/) and the
# two shared_metadata/ mappings the dataset reads at init.
#
# Format: standard `md5sum` output -> "<md5hash>  <relative_path>".
# Paths are relative to ${DLRM_DATA_PATH}/processed_5b/, hence the ../ prefix on
# the shared_metadata entries.
#
# Verify with:
#
#   DLRM_DATA_PATH=/path/to/dlrm_data ./verify_dataset.sh
#
# or directly:
#
#   cd "${DLRM_DATA_PATH}/processed_5b"
#   md5sum -c <repo>/md5sums_yambda_5b_processed.txt
#
# The direct form assumes the full local-build layout. A prepared download from
# MLCommons ships no parquet -- only item_popularity.npy and the two mappings of
# the seven below -- so use verify_dataset.sh, which checks what is present, or
# add --ignore-missing. The derived cache that download carries is covered
# separately by sha256sums_yambda_5b_cache.txt.
#
# These pin the canonical preprocessing output: 47,710,942,572 bytes across the
# seven files below, produced by ./download_dataset.sh from the yandex/yambda
# HuggingFace snapshot dd6f3a19eef5866e346c3270e098baa641a44948.
#
# Regenerate (emits these lines, in this order):
#
#   cd "${DLRM_DATA_PATH}/processed_5b"
#   md5sum train_sessions.parquet test_events.parquet session_index.parquet \
#          item_popularity.npy split_meta.json \
#          ../shared_metadata/artist_item_mapping.parquet \
#          ../shared_metadata/album_item_mapping.parquet
#
# The two item mappings are included because DLRMv4YambdaDataset._load_metadata
# derives the embedding-table size from the maximum item_id across them. A
# truncated or stale mapping would not raise; it would silently change the model
# being benchmarked.
#
# Not covered here: shared_metadata/embeddings.parquet is unused by HSTU
# training, raw/5b/multi_event.parquet is an input to preprocessing rather than
# to training, and hstu_cache_L4086/ is a derived mmap cache the dataset rebuilds
# on demand.
#
# Note that these hash the byte-for-byte artifacts, so they verify a copy or a
# download of this dataset. Re-running preprocessing on another machine can
# produce logically identical parquet files with different bytes, since the
# parquet writer records its own version and row-group layout.
#
